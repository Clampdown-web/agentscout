How does AgentScout check which MCP servers are reachable?

Once a day, AgentScout requests each listed MCP server URL and, when it is a different link, its GitHub URL. The request is HEAD, then GET, with a 20-second timeout. If that fails on TLS or gets no response, it retries once with a browser user agent. A server counts as reachable when its stored label is OK or Reachable, blocks automated checks. OK is HTTP 200-399 or 405, and also 401, 403 or 429 when the GitHub URL succeeded or that URL is the only one checked. Reachable, blocks automated checks means those 401, 403 or 429 responses without a harder error. Any other checked result is not reachable. A server missing from the check file is not yet checked and is not counted. The last-checked time is the checked field, in America/Los_Angeles. The rows are on the MCP status page and in status.json.

How to choose

  • Servers that can move money are labelled Moves funds on AgentScout. Give them a separate wallet holding only what the agent needs, with spend limits where the server supports them.
  • Pair any wallet server with a safety check (GoPlus, Tanod, CoinGraph Wallet Guard, Webacy) so the agent screens a recipient or token before it signs.
  • Check custody: some servers keep keys on your machine, others in a hosted wallet such as Coinbase's.
  • Only connect servers you trust: an MCP server can read and act on whatever its credentials allow.
