About Kortix CompanyOS

Kortix CompanyOS is listed in our business agents category and is aimed at builders. Kortix CompanyOS is an open-source, cloud-native agent harness for companies: always-on agents start from schedules, webhooks, app events or team messages, run in parallel swarms on their own persistent cloud computers with shared company memory, connect to 3,000+ apps and land changes through team-approved reviews. Pricing, as the maker states it: Open source + cloud. Maturity: Mature. We last checked the official link on 2026-11-09.

What is Kortix CompanyOS?

Kortix CompanyOS is a cloud-native agent harness. The README says you write agents on pi, keep them in one git repo, and start them from schedules, signed webhooks, connector events, app events or team messages. Each session gets its own cloud computer that sleeps after it is idle and wakes with its history. A built-in agent, My Kortix, routes work. Changes that land on main go through a change request a person approves.

The README says agents can use more than 3,000 apps plus MCP, OpenAPI, GraphQL and raw HTTP, and that credentials stay on the server. You can run it on Kortix Cloud, in a VPC, or on your own network from the same images. The licence file is the Elastic License 2.0. That is not an OSI open-source licence: you may not offer the software to third parties as a hosted or managed service that exposes a substantial part of its features. The README still describes the project as open source. The licence text is the restriction that applies.

Sources: github.com/kortix-ai/CompanyOS, github.com/kortix-ai/CompanyOS/blob/main/README.md, github.com/kortix-ai/CompanyOS/blob/main/LICENSE, kortix.com/docs/guide and our directory listing, checked 2026-11-09.

Who is Kortix CompanyOS for?

Teams who want always-on agents in a repo they own, with a human approval before a change reaches main, and who have read the Elastic License before they host it for anyone else.

Pros and cons

Pros

  • The README says a person approves what reaches main, and that a filter in code can drop events before a model runs.
  • The same images run on Kortix Cloud, a VPC or an on-prem network.
  • Secrets are encrypted at rest with a key per project, according to the README.

Cons

  • Elastic License 2.0 forbids offering the software as a hosted or managed service. Read LICENSE before you resell access.
  • The 3,000+ app figure is the README's count. This listing did not re-count the connector catalog.
  • Models are separate. The README lists Kortix-managed models, your own keys, or a ChatGPT or Claude subscription, through the Kortix LLM gateway.
  • A sleeping computer is the idle behaviour the README describes, about 15 to 20 minutes after the last turn. It is not a machine that stays up with no idle timeout.

Setup

  1. Install the CLI with the README's command, curl -fsSL https://kortix.com/install | bash.
  2. Run kortix init to scaffold kortix.yaml, agents, skills and runtime config.
  3. Run kortix ship to push the repo and bring it up in the cloud. kortix cr ls lists change requests. kortix chat talks to a session from the terminal.
  4. Or sign up at kortix.com and create a project with no CLI. Read the Elastic License in the repository before you expose the software as a service.
